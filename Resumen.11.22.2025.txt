================================================================================
POSIBLES PROBLEMAS Y SOLUCIONES
================================================================================

PROBLEMA 1: El frontend no carga después de reiniciar
------------------------------------------------------
Solución:
1. Verificar que el backend esté corriendo (http://localhost:5000/health)
2. Verificar que PostgreSQL esté corriendo
3. Limpiar cache del navegador
4. En frontend: rm -rf node_modules && npm install

PROBLEMA 2: Error "Cannot read property of undefined" en aprobación
--------------------------------------------------------------------
Solución:
1. Verificar que los datos del reporte incluyan los campos de aprobación
2. Verificar que el useEffect de sincronización esté ejecutándose
3. Revisar console.log para ver qué datos llegan del backend

PROBLEMA 3: Los botones de Aprobar/Rechazar no aparecen
--------------------------------------------------------
Solución:
1. Verificar que currentApprovalStep > 0
2. Verificar que isCurrentApprover() retorna true
3. Revisar que el usuario actual esté en la lista de aprobadores del Issue Card
4. Verificar que el paso actual coincida con la posición del aprobador

PROBLEMA 4: Campos no se bloquean correctamente
------------------------------------------------
Solución:
1. Verificar que fieldsLocked esté calculándose correctamente
2. Verificar que data.d1D2D3ApprovalStatus tenga el valor correcto
3. Revisar que currentUser.id esté disponible
4. Verificar rol del usuario (admins nunca se bloquean)

NOTAS IMPORTANTES
================================================================================

1. CONVENCIONES DE NOMBRES:
   - Backend usa snake_case (approval_1_status)
   - Frontend usa camelCase (approval1Status)
   - La conversión se hace automáticamente via utils/caseTransform.js

2. ROLES DE USUARIO:
   - 'Administrador' o 'Admin' = Acceso completo siempre
   - Emisor = Solo edita en draft y rejected
   - Aprobadores (Issue Card) = Editan durante pending_approval

3. ESTADOS DE APROBACIÓN (d1_d2_d3_approval_status):
   - 'draft' = Borrador inicial
   - 'pending_approval_1' = Esperando Aprobador 1
   - 'pending_approval_2' = Esperando Aprobador 2
   - 'pending_approval_3' = Esperando Aprobador 3
   - 'approved' = Completamente aprobado
   - 'rejected_by_a1' = Rechazado por Aprobador 1
   - 'rejected_by_a2' = Rechazado por Aprobador 2
   - 'rejected_by_a3' = Rechazado por Aprobador 3

4. CURRENT_APPROVAL_STEP:
   - 0 = Draft o Rejected (no en aprobación)
   - 1 = Esperando Aprobador 1
   - 2 = Esperando Aprobador 2
   - 3 = Esperando Aprobador 3
   - 4 = Completamente aprobado

5. SEGURIDAD:
   - Todos los endpoints de aprobación requieren autenticación (verifyToken)
   - Los comentarios de rechazo son obligatorios
   - Las transacciones de BD usan BEGIN/COMMIT/ROLLBACK para integridad
   - Se recomienda agregar validación de permisos en backend
