RESUMEN GENERAL:
----------------
Se ha implementado un sistema completo de aprobaciones en cascada para reportes
8D, con 15 estados diferentes que cubren todo el flujo desde borrador hasta
cierre final.


================================================================================
1. BASE DE DATOS
================================================================================

TABLA CREADA: eightd_approvals
-------------------------------
Ubicación: backend/migrations/create_eightd_approvals.sql

Campos:
  - id (serial)                 - ID único de la aprobación
  - report_id (integer)         - FK a eightd_reports
  - section (varchar)           - 'issue', 'countermeasure', 'confirmation'
  - approver_level (integer)    - 1, 2, o 3 (nivel del aprobador)
  - user_id (integer)           - FK a users (quién aprobó/rechazó)
  - action (varchar)            - 'approved' o 'rejected'
  - comments (text)             - Comentarios (obligatorio en rechazos)
  - created_at (timestamp)      - Fecha de la acción

Índices:
  ✅ idx_eightd_approvals_report_id (reporte)
  ✅ idx_eightd_approvals_section (sección)
  ✅ idx_eightd_approvals_user_id (usuario)


COLUMNA AGREGADA: eightd_reports.status
----------------------------------------
Tipo: VARCHAR(50)
Default: 'draft'

Estados posibles (15 en total):
  1.  draft                      - Borrador inicial
  2.  issue_approval_1           - Esperando Issue Aprobador 1
  3.  issue_approval_2           - Esperando Issue Aprobador 2
  4.  issue_approval_3           - Esperando Issue Aprobador 3
  5.  issue_approved             - Issue completado
  6.  countermeasure_in_progress - Countermeasure Primary trabajando
  7.  countermeasure_approval_1  - Esperando Countermeasure Aprobador 1
  8.  countermeasure_approval_2  - Esperando Countermeasure Aprobador 2
  9.  countermeasure_approval_3  - Esperando Countermeasure Aprobador 3
  10. countermeasure_approved    - Countermeasure completado
  11. confirmation_in_progress   - Confirmation Primary trabajando
  12. confirmation_approval_1    - Esperando Confirmation Aprobador 1
  13. confirmation_approval_2    - Esperando Confirmation Aprobador 2
  14. confirmation_approval_3    - Esperando Confirmation Aprobador 3
  15. closed                     - 8D completado y cerrado

2. BACKEND - ENDPOINTS Y LÓGICA

ARCHIVO PRINCIPAL: endpoints/approvalsEndpoints.js
--------------------------------------------------

STATE MACHINE:
--------------
Objeto que define todas las transiciones de estados posibles.
Cada estado tiene:
  - next: Estado siguiente al aprobar
  - previous: Estado anterior al rechazar
  - section: Sección a la que pertenece
  - level: Nivel de aprobador (1, 2, 3)


FUNCIONES PRINCIPALES:
----------------------

1. getNextState(reportId, currentState)
   - Calcula el siguiente estado dinámicamente
   - Salta aprobadores si no están asignados
   - Evita estados innecesarios

2. getPreviousState(currentState)
   - Obtiene el estado anterior para rechazos
   - Permite regresar en el flujo


ENDPOINTS CREADOS:
------------------

📤 POST /8d/reports/:id/submit
   Descripción: Enviar reporte desde draft a aprobación
   Auth: Requiere token JWT
   Body: (vacío)
   Response:
     {
       "success": true,
       "message": "Reporte enviado a aprobación",
       "newStatus": "issue_approval_1"
     }

✅ POST /8d/reports/:id/approve
   Descripción: Aprobar una sección del 8D
   Auth: Requiere token JWT
   Body:
     {
       "section": "issue|countermeasure|confirmation",
       "level": 1|2|3,
       "comments": "Comentarios opcionales"
     }
   Validaciones:
     - Usuario debe ser el aprobador asignado
     - Estado debe corresponder a la aprobación solicitada
     - Registra aprobación en eightd_approvals
     - Actualiza estado del reporte

❌ POST /8d/reports/:id/reject
   Descripción: Rechazar una sección del 8D
   Auth: Requiere token JWT
   Body:
     {
       "section": "issue|countermeasure|confirmation",
       "level": 1|2|3,
       "comments": "Razón del rechazo (OBLIGATORIO)"
     }
   Validaciones:
     - Usuario debe ser el aprobador asignado
     - Comentarios son obligatorios
     - Regresa al estado anterior
     - Registra rechazo en eightd_approvals

📊 GET /8d/reports/:id/approval-status
   Descripción: Obtener estado de aprobación completo
   Auth: Requiere token JWT
   Response:
     {
       "report_id": 123,
       "current_status": "issue_approval_2",
       "created_by": 5,
       "created_at": "2025-11-14T...",
       "updated_at": "2025-11-14T...",
       "pending_approver": {
         "section": "issue",
         "level": 2,
         "users": [{ id, firstName, lastName, ... }]
       },
       "approval_history": [
         {
           id, section, approver_level, action, comments,
           first_name, last_name, email, position, created_at
         }
       ]
     }

4. FLUJO DE USUARIO
================================================================================

FLUJO COMPLETO:
---------------

1. CREACIÓN DEL REPORTE (DRAFT)
   Usuario crea un reporte 8D
   Estado inicial: 'draft'
   ✅ Solo el creador puede ver y editar

2. ENVÍO A APROBACIÓN
   Click en "📤 Enviar a Aprobación"
   Estado cambia a: 'issue_approval_1'
   ✅ El Issue Aprobador 1 recibe notificación

3. APROBACIÓN ISSUE - NIVEL 1
   Aprobador 1 revisa el reporte

   OPCIÓN A - APROBAR:
     ✅ Click en "Aprobar"
     ✅ Comentarios opcionales
     ✅ Estado cambia a: 'issue_approval_2'
     ✅ Pasa a Aprobador 2

   OPCIÓN B - RECHAZAR:
     ❌ Click en "Rechazar"
     ❌ Comentarios OBLIGATORIOS
     ❌ Estado regresa a: 'draft'
     ❌ Vuelve al creador para corregir

4. APROBACIÓN ISSUE - NIVEL 2
   (Si hay Aprobador 2 asignado)
   Mismo flujo que Nivel 1
   Al aprobar → 'issue_approval_3'
   Al rechazar → 'issue_approval_1'

5. APROBACIÓN ISSUE - NIVEL 3
   (Si hay Aprobador 3 asignado)
   Al aprobar → 'issue_approved'
   Al rechazar → 'issue_approval_2'

6. COUNTERMEASURE IN PROGRESS
   Primary de Countermeasure trabaja
   Estado: 'countermeasure_in_progress'
   Al completar → 'countermeasure_approval_1'

7. APROBACIÓN COUNTERMEASURE (NIVELES 1-2-3)
   Mismo flujo en cascada que Issue
   Estados: countermeasure_approval_1/2/3
   Al completar todo → 'countermeasure_approved'

8. CONFIRMATION IN PROGRESS
   Primary de Confirmation trabaja
   Estado: 'confirmation_in_progress'
   Al completar → 'confirmation_approval_1'

9. APROBACIÓN CONFIRMATION (NIVELES 1-2-3)
   Mismo flujo en cascada
   Estados: confirmation_approval_1/2/3
   Al completar Nivel 3 → 'closed'

10. CERRADO (CLOSED)
    ✅ 8D completamente aprobado
    ✅ No se permiten más cambios
    ✅ Visible en dashboard como cerrado


REGLAS DE NEGOCIO:
------------------
1. Si no hay aprobador asignado en un nivel, se salta automáticamente
2. Al rechazar, siempre regresa al paso ANTERIOR (no siempre al creador)
3. Comentarios son obligatorios en rechazos
4. Solo el aprobador asignado puede aprobar/rechazar
5. El creador puede ver el estado pero no puede aprobar
6. Los aprobadores pueden editar antes de aprobar
7. En estado 'closed' nadie puede editar

5. INTEGRACIÓN CON EL SISTEMA EXISTENTE
================================================================================

CÓMO USAR EN 8DWorkflow.js:
----------------------------

1. Importar componentes:
   ```javascript
   import ApprovalPanel from '../components/8D/ApprovalPanel';
   import StatusBadge from '../components/8D/StatusBadge';
   ```

2. Agregar estado para el usuario actual:
   ```javascript
   const [currentUser, setCurrentUser] = useState(null);
   ```

3. Cargar usuario al montar componente:
   ```javascript
   useEffect(() => {
     // Obtener usuario del localStorage o contexto
     const user = JSON.parse(localStorage.getItem('user'));
     setCurrentUser(user);
   }, []);
   ```

4. Mostrar badge de estado en el header:
   ```javascript
   {workflowData?.status && (
     <StatusBadge status={workflowData.status} />
   )}
   ```

5. Agregar panel de aprobaciones:
   ```javascript
   <ApprovalPanel
     reportId={workflowData?.id}
     currentUser={currentUser}
     onStatusChange={() => {
       // Recargar datos del reporte
       loadReportData();
     }}
   />
   ```
