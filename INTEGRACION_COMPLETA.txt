2. CÓMO USAR EL SISTEMA DE APROBACIONES
================================================================================

PASO 1: CREAR UN REPORTE 8D
----------------------------
1. Login en el sistema
2. Ir a "Nuevo 8D"
3. Completar datos básicos (D1-D2-D3)
4. Asignar equipo:
   - Primary de Issue
   - Aprobadores 1, 2, 3 para Issue (opcional)
   - Primary de Countermeasure
   - Aprobadores 1, 2, 3 para Countermeasure (opcional)
   - Primary de Confirmation
   - Aprobadores 1, 2, 3 para Confirmation (opcional)
5. Guardar reporte

Estado: DRAFT (Borrador)
Badge: Gris - "Borrador"


PASO 2: ENVIAR A APROBACIÓN
----------------------------
1. Abrir el reporte guardado
2. Ver el panel de aprobaciones en la parte superior
3. Click en "📤 Enviar a Aprobación"
4. Confirmar

Resultado:
- Estado cambia automáticamente
- Si hay Aprobador 1 en Issue → status: 'issue_approval_1'
- Si no hay aprobadores → salta a siguiente sección
- Badge cambia a Amarillo


PASO 3: APROBAR/RECHAZAR
-------------------------

A) APROBAR:
   1. Login como Aprobador asignado
   2. Abrir el reporte
   3. Click en "🔍 Revisar y Aprobar/Rechazar"
   4. Click en "✅ Aprobar"
   5. Agregar comentarios opcionales
   6. Click en "Confirmar Aprobación"

   Resultado:
   - Aprobación registrada en eightd_approvals
   - Estado avanza al siguiente nivel
   - Timeline actualizado

B) RECHAZAR:
   1. Login como Aprobador asignado
   2. Abrir el reporte
   3. Click en "🔍 Revisar y Aprobar/Rechazar"
   4. Click en "❌ Rechazar"
   5. Escribir razón del rechazo (OBLIGATORIO)
   6. Click en "Confirmar Rechazo"

   Resultado:
   - Rechazo registrado con comentarios
   - Estado regresa al paso ANTERIOR
   - Emisor puede corregir y reenviar


PASO 4: SEGUIMIENTO
--------------------
- El badge de estado se actualiza automáticamente
- Timeline muestra todo el historial
- Notificación visual de quién debe aprobar
- Colores:
  * Gris: Draft
  * Amarillo: Esperando aprobación
  * Azul: En progreso (Primary trabajando)
  * Verde: Aprobado/Cerrado

3. FLUJO COMPLETO EJEMPLO
================================================================================

ESCENARIO: 8D con todos los aprobadores asignados

1. CREADOR crea reporte → Status: 'draft'

2. CREADOR envía a aprobación → Status: 'issue_approval_1'
   → Aprobador Issue Nivel 1 recibe

3. APROBADOR ISSUE 1 aprueba → Status: 'issue_approval_2'
   → Aprobador Issue Nivel 2 recibe

4. APROBADOR ISSUE 2 RECHAZA → Status: 'issue_approval_1'
   → Regresa a Aprobador Issue Nivel 1

5. APROBADOR ISSUE 1 corrige y aprueba → Status: 'issue_approval_2'
   → Aprobador Issue Nivel 2 recibe nuevamente

6. APROBADOR ISSUE 2 aprueba → Status: 'issue_approval_3'
   → Aprobador Issue Nivel 3 recibe

7. APROBADOR ISSUE 3 aprueba → Status: 'issue_approved'
   → Pasa automáticamente a Countermeasure

8. Status: 'countermeasure_in_progress'
   → Primary de Countermeasure trabaja

9. PRIMARY COUNTERMEASURE completa → Status: 'countermeasure_approval_1'
   → Aprobador Countermeasure Nivel 1 recibe

10-12. Se repite flujo de aprobaciones para Countermeasure
    → Status final: 'countermeasure_approved'

13. Status: 'confirmation_in_progress'
    → Primary de Confirmation trabaja

14-16. Se repite flujo de aprobaciones para Confirmation
    → Status final: 'closed'

17. REPORTE CERRADO ✅
    Badge: Verde - "Cerrado"
    No se permiten más ediciones

4. CARACTERÍSTICAS ESPECIALES
================================================================================

SALTO DE APROBADORES:
----------------------
Si no hay aprobador asignado en un nivel, el sistema salta automáticamente.

Ejemplo:
  Asignados: Aprobador 1 y Aprobador 3 (sin Aprobador 2)
  Flujo: approval_1 → approval_3 (salta el 2)


PERMISOS:
---------
✅ Creador: Puede ver, editar en draft, enviar a aprobación
✅ Aprobador asignado: Puede ver, aprobar, rechazar
✅ Primary: Puede ver, editar su sección, completar
✅ Admin: Puede ver todos los reportes
❌ Otros usuarios: Solo pueden ver


VALIDACIONES:
-------------
✅ Comentarios obligatorios en rechazos
✅ Solo aprobadores asignados pueden aprobar/rechazar
✅ No se puede aprobar si no está en el estado correcto
✅ No se puede editar después de 'closed'


HISTORIAL COMPLETO:
-------------------
El timeline muestra:
  - Quién aprobó/rechazó
  - Cuándo
  - Qué sección y nivel
  - Comentarios
  - Posición del usuario

6. ENDPOINTS DISPONIBLES
================================================================================

BASE URL: http://localhost:5000

1. POST /8d/reports/:id/submit
   Headers: { Authorization: Bearer <token> }
   Response: { success, message, newStatus }

2. POST /8d/reports/:id/approve
   Headers: { Authorization: Bearer <token> }
   Body: { section, level, comments? }
   Response: { success, message, newStatus }

3. POST /8d/reports/:id/reject
   Headers: { Authorization: Bearer <token> }
   Body: { section, level, comments }
   Response: { success, message, newStatus }

4. GET /8d/reports/:id/approval-status
   Headers: { Authorization: Bearer <token> }
   Response: {
     report_id,
     current_status,
     created_by,
     created_at,
     updated_at,
     pending_approver: { section, level, users[] },
     approval_history: []
   }
