# Resumen de la Sesión - Quality Alert System

## Estado Actual del Proyecto

### Arquitectura General
- **Frontend**: React 18+ con React Router v6, ejecutándose en puerto 3000
- **Backend**: Node.js + Express, ejecutándose en puerto 5000
- **Almacenamiento**: En memoria (arrays en backend/server.js)
- **Estilos**: CSS inline, sin framework CSS externo

### Funcionalidades Principales Implementadas

#### 1. **Sistema de Gestión de Clientes**
- **Lista de clientes** (`/clients`) - ClientsList.js
- **Detalle de cliente** (`/clients/:clientId`) - ClientDetail.js
- **Crear cliente** (`/clients/new`) - CreateClient.js
- **Editar cliente** (`/clients/:clientId/edit`) - CreateClient.js (mismo componente, modo edición)

#### 2. **Sistema de Gestión de Jobs**
- **Lista de jobs** (`/jobs`) - JobsList.js
- **Detalle de job** (`/jobs/:jobId`) - JobDetail.js
- **Crear job** (`/jobs/new`) - CreateJob.js

#### 3. **CreateJob - Características Especiales**
**Selector de Tipo de Job** (3 opciones):
- **"Campaña de calidad"**: Sin sección de milestones, aspectos de calidad personalizables
- **"Nueva tarea"**: Con milestones y aspectos de calidad personalizables
- **"Proyecto"**: Con milestones, pero aspectos de calidad fijos = "Juicio del Proyecto" únicamente

**Secciones del formulario**:
- Información básica (nombre, número, cliente, tipo)
- Milestones (condicional - se oculta para Campaña de calidad)
- Aspectos de calidad (auto-asigna "Juicio del Proyecto" para Proyectos)
- Documentos (se guardan en el cliente con referencia al job)

#### 4. **CreateClient - Características**
**Modo dual** (crear/editar):
- Detecta si hay `clientId` en URL para determinar el modo
- En modo edición: carga datos existentes con `useEffect`
- Muestra spinner mientras carga datos en modo edición

**Secciones del formulario**:
- Información Básica (nombre, alias, vendor number, website, estado, firma requerida)
- Información Corporativa (dirección, teléfono, fax)
- Información de Facturación (dirección facturación, frecuencia, período)
- Contactos (tabla dinámica con agregar/eliminar)
- Documentos (tabla dinámica con tipos predefinidos: Cotización, Correo de Aprobación, Instrucciones, Contrato, Orden de Compra, Certificado, Otro)

### Cambio Importante de Esta Sesión

**ANTES**: ClientDetail tenía edición inline (campos se convertían en inputs, botones Save/Cancel)
**AHORA**: ClientDetail solo muestra datos, botón "Edit" navega a `/clients/:clientId/edit` que abre el formulario completo pre-poblado

**Razón del cambio**: Evitar complicaciones con edición pestaña por pestaña en ClientDetail (que tiene múltiples tabs: profile, contacts, documents, jobs, analytics, billing)

### Relación Documentos-Jobs-Clientes

**Arquitectura implementada**:
- Los documentos subidos en CreateJob se guardan en el array `documents` del cliente
- Cada documento del job incluye: `jobId`, `jobNumber`, `jobName` como referencias
- Esto permite centralizar documentos en el cliente pero filtrarlos por job
- Backend maneja esta lógica en el endpoint POST `/jobs/create` (líneas 1293-1311 de server.js)

### Backend - Endpoints Clave

**Clientes**:
- `GET /clients` - Lista todos los clientes
- `GET /clients/:id` - Obtiene un cliente específico
- `POST /clients/create` - Crea nuevo cliente
- `PUT /clients/:id` - Actualiza cliente existente
- `DELETE /clients/:id` - Elimina cliente

**Jobs**:
- `GET /jobs` - Lista todos los jobs (acepta filtro `?clientId=`)
- `GET /jobs/:id` - Obtiene un job específico
- `POST /jobs/create` - Crea nuevo job (incluye lógica para documentos)

### Estructura de Datos

**Cliente**:
```javascript
{
  id, name, alias, vendorNumber,
  corporateAddress, corporatePhone, corporateFax,
  billingAddress, billingFrequency, billingPeriod,
  website, isActive, requiresSignature,
  contacts: [{name, title, email, phone}],
  documents: [{name, type, description, fileName, fileSize, uploadDate, jobId?, jobNumber?, jobName?}]
}
```

**Job**:
```javascript
{
  id, jobNumber, jobName, clientId, jobType,
  milestones: [{name, targetDate}],
  qualityAspects: [{name, criteria: []}],
  documents: [{name, type, description, fileName, fileSize, uploadDate}]
}
```
