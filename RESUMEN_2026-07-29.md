### Estación RELEASE_OK - Cierre de Ciclo de Calidad (COMPLETADO)
Implementación de estación final de liberación que marca el cierre del ciclo de calidad.

| Componente | Cambio |
|------------|--------|
| **Migración** | `115_release_ok_station.sql` - estación + campos archivado + función release_unit |
| **Backend** | `releaseOkEndpoints.js` - 5 endpoints (station, validate, release, pending, history) |
| **Backend** | Modificado `server.js` para registrar endpoints |
| **Frontend** | Componente `ReleaseOK.js` - UI completa de liberación |
| **Frontend** | Ruta `/release-ok` agregada en `App.js` |
| **Frontend** | Enlace en `Home.js` menú principal |
| **Docs** | `docs/RELEASE_OK_DESIGN.md` - documentación completa |

### Flujo Implementado
```
Serial llega a RELEASE_OK
    ↓
Sistema valida automáticamente:
    ├─ ¿Defectos abiertos?
    └─ ¿Specs NOK?
    ↓
TODO OK → [Liberar] → RELEASED + is_archived = true
    ó
BLOQUEO → Lista de pendientes → [Ir a Hospital]
```

### Decisiones de Diseño Clave
1. **Sin override**: No hay forma de liberar con defectos o specs NOK
2. **Sin excepciones**: Las desviaciones se manejan en Hospital, no en Release
3. **Estación global**: Una sola RELEASE_OK para todo el sistema (no por cliente)
4. **Archivado automático**: Parte liberada = is_archived = true (solo lectura)
5. **Protección de estación**: Trigger impide editar/borrar estaciones del sistema

### Campos Nuevos en DB

**inspection_stations:**
- `is_system BOOLEAN` - Estaciones del sistema (no editables)

**unit_registry:**
- `is_archived BOOLEAN` - Parte cerró ciclo de calidad
- `archived_at TIMESTAMP` - Cuándo se archivó
- `released_by INTEGER` - Quién liberó
