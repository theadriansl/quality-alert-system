[COMPLETADO] Error 500 - Invalid input syntax for integer
   Problema: PostgreSQL rechazaba empty string ("") para campo INTEGER
   Error: "invalid input syntax for type integer: ''"
   Causa: Frontend enviaba managerId = "" cuando estaba vacio
   PostgreSQL espera: integer o NULL, NO string vacio

   Solucion implementada:
   - Validacion en updateUser antes de insertar en values array
   - Conversion de empty strings a NULL para campos integer
   - Codigo agregado (lineas 147-151):
     ```javascript
     let value = snakeData[key];
     if ((key === 'manager_id' || key === 'hierarchy_level') && value === '') {
       value = null;
     }
     values.push(value);
     ```
   - Aplica a: manager_id, hierarchy_level
   - NULL es aceptado por PostgreSQL para campos INTEGER nullable
   Archivo: backend/endpoints/usersEndpoints.js
   Estado: RESUELTO

NOTAS TECNICAS IMPORTANTES - SESION 2
================================================================================

1. MANEJO DE NULL vs EMPTY STRING
   PostgreSQL:
   - Campos INTEGER NO aceptan empty string ("")
   - Campos INTEGER aceptan NULL
   - VARCHAR acepta tanto "" como NULL

   Solucion implementada:
   - Validacion en backend antes de query
   - Conversion de "" a NULL para campos: manager_id, hierarchy_level
   - Se aplica en updateUser() lineas 147-151

2. ESTRUCTURA DE JERARQUIA
   Diseno:
   - manager_id es FK a users.id con ON DELETE SET NULL
   - Permite estructura recursiva (managers de managers)
   - hierarchy_level facilita queries y filtros
   - NULL en manager_id = top level (Director/CEO)

   Ventajas:
   - Facil filtrar por nivel jerarquico
   - Facil obtener subordinados de un manager
   - Facil validar que manager sea de nivel superior
   - Indices optimizan queries

3. FILTRADO DE MANAGERS EN FRONTEND
   Logica implementada:
   - Excluir usuario actual (no reportar a si mismo)
   - Solo mostrar usuarios con hierarchy_level menor (superior)
   - Ordenar por nivel (Directores primero, luego Managers, etc)
   - Formato legible con posicion y nivel

4. TRANSFORMACION BIDIRECCIONAL
   Frontend -> Backend (request):
   - managerId -> manager_id
   - hierarchyLevel -> hierarchy_level
   - firstName -> first_name

   Backend -> Frontend (response):
   - manager_id -> managerId
   - hierarchy_level -> hierarchyLevel
   - first_name -> firstName

   Utilidad: transformToSnakeCase / transformToCamelCase

5. CASCADAS Y RELACIONES
   manager_id:
   - ON DELETE SET NULL (no elimina usuarios subordinados)
   - Si se elimina manager, subordinados quedan sin manager
   - Permite reorganizacion de estructura
