  [MÓDULO: QAR - QUALITY ACTION REQUEST]
  ================================================================================

  ├── OBJETIVO
  │   Gestión integral del ciclo de vida de alertas de calidad con:
  │   - Disparo automático por umbrales de defectos
  │   - Seguimiento de respuestas y validaciones

  │   ├── Fotos NOK/OK
  │   ├── Usuarios (destinatarios respuesta/validación)
  │   └── Cliente/Proyecto/Parte

  ├── PROCESO (Flujo de Estados)
  │   │
  │   ├── [DISPARO]
  │   │   ├── Manual: Usuario crea QAR seleccionando cliente/parte/defectos
  │   │   └── Automático: Umbral alcanzado durante inspección
  │   │       └── POST /qar/check-threshold → Modal "¿Crear QAR?"
  │   │           ├── Aceptar → QARCreate pre-llenado
  │   │           └── Declinar → qar_declined_history (trazabilidad)
  │   │
  │   ├── [EMITIDO]
  │   │   ├── QAR creado con número automático (QAR-YYYY-NNNN)
  │   │   ├── Defectos vinculados (qar_defects)
  │   │   ├── Destinatarios asignados (response/validation)
  │   │   └── Timer SLA iniciado
  │   │
  │   ├── [RESPONDIDO]
  │   │   ├── POST /qar/:id/respond
  │   │   ├── Campos: rootCause, correctiveAction, resolutionNotes
  │   │   ├── Archivos adjuntos (evidencia)
  │   │   └── Pasa a validación
  │   │
  │   └── [CIERRE]
  │       ├── POST /qar/:id/validate
  │       ├── approved=true → CERRADO (validation_status='approved')
  │       └── approved=false → RECHAZADO → Vuelve a RESPONDIDO
  │
  ├── OUTPUTS
  │   ├── QAR cerrados con root cause documentado
  │   ├── IE-QAR (Índice de Efectividad): defectos pre vs post QAR
  │   ├── Métricas SLA (tiempo respuesta/cierre)
  │   ├── Historial de acciones (qar_comments)
  │   └── Dashboard ejecutivo con KPIs

  ├── REGLAS DE NEGOCIO
  │   ├── Umbrales default:
  │   │   ├── CRITICAL/ALTA: 1 defecto en 1 hora
  │   │   ├── MAJOR: 3 defectos en 4 horas
  │   │   └── MINOR: 5 defectos en 8 horas
  │   ├── SLA default (horas):
  │   │   ├── Crítico: 4h respuesta / 24h cierre
  │   │   ├── Alta: 8h respuesta / 48h cierre
  │   │   ├── Mayor: 24h respuesta / 72h cierre
  │   │   └── Menor: 48h respuesta / 120h cierre
  │   ├── Solo usuarios con can_validate_qar pueden aprobar/rechazar
  │   └── Defectos marcados con qar_id al vincularse

  ├── INTEGRACIONES / RELACIONES
  │   ├── ← DEFECTOS: Disparo automático por umbral
  │   ├── ← CONFIGURACIÓN: Umbrales y SLA por severidad
  │   ├── → 8D: QAR puede escalar a 8D (trigger_type='escalation')
  │   ├── → DASHBOARD: Métricas IE-QAR, SLA, tendencias
  │   └── ↔ USUARIOS: Destinatarios, validadores, responsables

  ├── TABLAS PRINCIPALES
  │   ├── quality_alerts (core)
  │   ├── qar_defects (vínculos)
  │   ├── qar_recipients (destinatarios)
  │   ├── qar_comments (timeline)
  │   ├── qar_sla_config (configuración)
  │   ├── qar_response_files (archivos)
  │   └── qar_declined_history (rechazos)

      ├── Dashboard identifica QARs en riesgo (vencidos sin validación)
      └── Fotos NOK/OK para evidencia visual

  ├── OBJETIVO

  │   - Revisión gerencial trimestral
  │   - Agregación KPIs de todos los módulos
  │   - Checklist 25 ítems (inputs 9.3.2 + outputs 9.3.3)
  │   - Seguimiento de acciones previas
  │   - Firmas digitales y gobernanza

  ├── INPUTS (ISO 9.3.2)
  │   ├── KPIs de 6 módulos:
  │   │   ├── 8D: openCount, closedCount, avgDaysToClose, onTimeRate, totalSavings
  │   │   ├── QAR: totalQars, openCount, criticalCount, majorCount, totalDefects

  │   ├── Acciones previas (status follow-up)
  │   ├── Checklist responses (25 ítems)
  │   └── Asistentes con firma

  ├── PROCESO (5 Tabs)
  │   │
  │   ├── [1. KPIs DEL PERÍODO]

  │   │   └── Display de 18 KPIs configurados
  │   │
  │   ├── [2. ACCIONES PREVIAS (9.3.2.a)]
  │   │   ├── Lista de acciones abiertas de revisiones anteriores
  │   │   ├── Status: pending → in_progress → completed
  │   │   ├── Due date tracking
  │   │   └── Responsable y notas de cierre
  │   │
  │   ├── [3. CHECKLIST 9.3]
  │   │   ├── 12 inputs ISO 9001:2015
  │   │   ├── 10 inputs IATF 16949:2016
  │   │   ├── 3 outputs (9.3.3)
  │   │   ├── Response: ok/partial/nok/n/a
  │   │   └── Comments + evidence links
  │   │
  │   ├── [4. DECISIONES]
  │   │   ├── Executive summary (texto libre)
  │   │   ├── Decisions array (description, responsible, dueDate, priority)
  │   │   └── Next review date
  │   │
  │   └── [5. ASISTENTES Y FIRMAS]
  │       ├── User selector (multi-select)
  │       ├── Presence toggle
  │       ├── Digital signature
  │       └── Auto-complete cuando todos firman

  ├── OUTPUTS (ISO 9.3.3)

  │   ├── Decisiones documentadas
  │   └── Firmas digitales

  ├── WORKFLOW
  │   │
  │   │  draft → in_progress → pending_signatures → completed
  │   │                  ↓
  │   │            cancelled (if needed)
  │   │
  │   └── Acciones auto-crean workload activities

  ├── REGLAS DE NEGOCIO
  │   ├── Acta number auto-generado con sequence
  │   ├── KPI snapshot inmutable una vez guardado

  │   ├── Acciones crean workload activities automáticamente
  │   ├── Status → completed cuando todos firman
  │   └── Frequency: quarterly (recommended)

  ├── INTEGRACIONES / RELACIONES
  │   ├── ← 8D: KPIs (open, closed, savings, on-time rate)
